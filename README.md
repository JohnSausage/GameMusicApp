# GameMusicApp

Compose game music on guitar: record or import a melody, get it as tab with notation, arrange tracks, play them with SoundFont or retro synth sounds, and export WAV/OGG/MIDI for Unity (and the score as a PDF).

- What the app should do: [REQUIREMENTS.md](REQUIREMENTS.md)
- Current state: milestone M0 (tech spike), see [docs/M0-spike-report.md](docs/M0-spike-report.md)

## Using the app

- **Start page:** create a new project, open a `.gmsong` file, or pick one of your recent projects.
- **Light and dark mode:** pick Light, Dark or System (follows the operating system) on the start page or under ☰ in the editor. In dark mode the score is drawn light on dark too.
- **Projects** are saved as `.gmsong` files (Ctrl+S); new ones go to `~/Documents/GameMusicApp/` by default. The recent list is kept in the app's settings folder (`~/.config/GameMusicApp/` on Linux). While a project has unsaved changes, a copy of them is kept there too (in `recovery/`), written a couple of seconds after each change. Saving, or closing without saving, removes it. If the app crashes or the computer goes off, the start page offers the changes under "Unsaved changes from last time": open them and save, or throw them away with ×.
- **Record / import:** in the tab editor, "● Record" in the top bar records your guitar (with a metronome count-in) or imports a WAV. Line up beat 1 on the waveform, let Basic Pitch transcribe it, check the result as tab and insert it into a track. Takes are saved in the project, so you can re-transcribe them later. The input you pick is remembered. "Latency" next to ● Record (also under ☰ → Audio and MIDI settings) sets how much later what you play arrives in the recording, so takes line up with the grid: "Measure" plays 8 clicks and times them coming back through the mic (hold it near the speakers, or with headphones play a muted string on each click), or type it in. Until then the app estimates it from the audio output.
- **Tuner:** ☰ → Tuner…, or "Tuner" next to ● Record, listens to the recording input and shows the nearest note, how many cents it is flat or sharp (green when it's within 5 cents) and which open string of the guitar or bass track that note is.
- **Sounds:** click a guitar, bass or keys track's sound in the track list to open its sound window. Pick a category (8-bit synth presets, your own presets, or an instrument family such as Piano, Guitar, Strings or Synth lead) and click a sound: it plays a note, and the track uses it. Any of the 128 General MIDI sounds works on any of these tracks, e.g. a piano on a guitar track. Try the sound on the on-screen keys, the computer keyboard (A–K, Z/X = octave) or a MIDI keyboard. Drum tracks use the drum kit or the 8-bit kit.
- **Retro sounds:** "★ Make it retro" gives every track an 8-bit sound by its role (and "↩ Original sounds" switches back). With an 8-bit sound, the sound window also shows the synth to shape it: pulse/triangle/saw/sine/noise, envelope, pitch sweep, vibrato and other wobbles, filter and bitcrusher. "Vary" next to the preset name nudges the 8-bit sound at random, as a starting point for a new one. Your own sounds can be saved as presets (kept in `~/.config/GameMusicApp/presets/`) or exported as `.gminst` files. A master bitcrusher makes the whole mix lo-fi.
- **Chip tricks and FM:** in the sound window, *Arpeggio* plays the notes of a chord one after the other on one voice, 15 to 60 notes per second (up, down, or up and down): the chip-music way to play chords on a single channel. *Echo* repeats the sound (level, time, and how loud each repeat is; the buttons set 1/16, 1/8, dotted 1/8 or 1/4 at the song's tempo). The *FM* waveform is the 16-bit sound of the Mega Drive / Genesis: one sine bending another, with ratio, depth (falling from the note's start to a sustain level), and feedback; "FM (16-bit)" in the sound browser has presets (bass, slap bass, brass, e-piano, bell, lead, organ).
- **Authentic mode:** *Console* in the Master card under the tracks limits the song to the sound channels of an old console: the NES (two pulse, one triangle, one noise), the Game Boy (two pulse, one wave for triangle, saw or sine, one noise) or the Mega Drive / Genesis (six FM, three square, one noise). Each channel plays one note at a time; a note that finds them all busy takes the one whose note started first, which ends there, as a console's sound driver does (an 8-bit kick takes the triangle from a triangle bass). An arpeggio or a mono synth needs one channel for its chord. A warning above the score says which bars need more channels (at the cursor's bar: how many notes of which kind) and which tracks use a sound the console doesn't have (a SoundFont instrument, a saw on the NES); those play as they are. Playback and export follow it; muted tracks take no channel.
- **Tab editor:** click a string in the tab or move with the arrow keys, then type fret numbers. Bars always stay full: shortening a note adds rests, lengthening it uses up what follows. "+ Bar" and "+ Section" after the last bar extend the song. Edit and Bar menus hold copy/paste and bar commands; "?" (bottom right, or the ? key) lists all keyboard shortcuts. The eye on a track's card leaves the track out of the score to keep it clear (it still plays; click again or pick the track to show it). The layout (Notation + tab or Tab only, Screen or Pages, zoom, tracks left out, minimized drum grid or piano roll) is saved with the project; new projects start with the layout you used last (with every track shown).
- **Sections and parts:** a song is a row of sections (Verse, Chorus, …), and in each section every track plays one of its parts, or nothing. Sections with the same notes share a part, so changing a note in one verse changes it in every verse that plays that part. Notes written into a silent section become a new part, named after the section. A section that gets longer or shorter in the score (bars inserted or deleted, a section started inside it) gets its own copy of a part it shares, and the other sections keep theirs. Part names are shown over the bar where a part starts, when the part plays in more than one section or is named differently from its section. Projects saved before parts existed get them when opened: sections with the same notes on a track share one part.
- **Arrangement:** the "Arrangement" tab above the score (Ctrl+Tab switches) shows the song as a grid: sections from left to right, a lane per track, and in each cell the part that track plays there, in the part's color. The section bar above has the section's name and length (a shorter part repeats to fill it, a longer one is cut off), ◀ ▶ to move it, Duplicate (a repeat playing the same parts), Delete, Loop it and "Show in score"; "+" adds a section at the end. With the mouse: drag a part onto another section of its track to play it there, drag a section by its name to move it, and drag its right edge to change its length (Esc cancels). Play, loop and the metronome work as in the score, with a playhead over the grid.
- **Editing parts:** under the grid, the part of the selected cell is shown on its own, as tab and notes, and edited like the score (Enter jumps there from the grid, Esc back). Changes go into every section that plays the part; the cells playing it are outlined. Above its score: the part's name and color, "Duplicate" (a copy with the same notes and color, played nowhere yet, to build a variation on; the copy opens for editing), "▶ Play part" (Space in the part plays it from the cursor; Loop repeats the whole part), "Place in “…”" to play it in the selected section, "Own copy" to change it in this section only, and "Silence". A silent cell offers "+ New part here". The palette at the bottom lists every part of every track and how often it plays: click one to edit it, drag it onto a section to play it there, "+" at the end of a track's row makes a new empty part for it (as long as the selected section). Parts no section plays stay in the palette; × or "Delete unused parts" removes them.
- **Song properties:** the time signature and key next to the tempo (e.g. "4/4 · C major", also under ☰) open the song's properties: title, author (shown as "Music by …" under the title, also in the PDF), tempo, time signature and key. The key sets the sharps or flats in the score (drum staves have none), and notes are written and named in it (B♭ in a key with flats). When the song has notes already, you choose: move them to the new key (every track but the drums, by the smallest step, e.g. C major → D major goes up a whole step) or keep them as they sound. MIDI export includes the key. Time signatures go from 2/4 to 12/8 (also 5/4, 7/8 and 9/8). If the bars get longer or shorter and there are notes, you choose how they are laid out, and the dialog says what each way does to your song: move the bar lines (every note stays where it is in time, a note across a new bar line is held over, and a section that no longer fills whole bars ends with rests; a part repeating in a section where its repeats no longer line up gets a copy for that section) or keep the bars (each bar keeps its notes from its start and sections keep their number of bars; longer bars end with rests, shorter ones lose what no longer fits). Bars of the same length, such as 4/4 and 2/2 or 3/4 and 6/8, keep their notes as they are.
- **Transpose:** Edit → Transpose… moves notes up or down by semitones: the selected beats, a track (with all its parts in an arranged song), or the whole song (every track but the drums; the key signature moves along). Guitar and bass either keep their strings (the frets move; a note its string can't reach goes to a free string close by) or get strings and frets chosen anew, close to where the hand is. A note out of the instrument's range goes an octave the other way. Alt+↑ / Alt+↓ moves the selection, or the beat at the cursor, a semitone.
- **Another string, same pitch:** Shift+↑ / Shift+↓ (or Edit → Move note to the string above / below) plays the note at the cursor on the next string up or down that is free and reaches it. A held note moves with the notes it is held from and into.
- **Tempo and time-signature changes:** Bar → *Tempo or time signature from here…* sets a new tempo and/or time signature from the cursor's bar until the next change (bar 1 has the song's own, in the song properties). The score shows them where they change, playback, the metronome, loops, the drum grid and the piano roll follow them, and MIDI export and the beat map include them. Bars that get another time signature keep their notes from their start: longer bars end with rests, shorter ones lose what no longer fits (the dialog says how many notes before you apply). *Remove the change* goes back to what the bars before have. A part edited on its own is in the tempo and time signature where it first plays. Changes stay at their bar when sections are moved in the arrangement. Takes are recorded in the tempo and time signature of the cursor's bar.
- **Bar check:** bars that are too short or too long for the time signature (e.g. from a project file edited elsewhere; editing in the app keeps bars full) are marked red in the score, and a line above it says by how much. *Fill with rests* or *Cut to fit* fixes the bar at the cursor, *Fit all* (also Bar → Fit bars to the time signature) every bar; cutting leaves out notes past the bar's end and cuts short the ones that ring past it. In an arranged song the part is fitted, so it fits wherever it plays.
- **Triplets:** "Triplet" in the toolbar (or /) makes the beat at the cursor, or the selected beats, triplets: three notes in the time of two, e.g. three triplet eighths in a quarter, shown with a 3 over them. A triplet group that isn't complete yet is filled up with triplet rests of its value, so you can type the other two notes into them. After you switch Triplet on, notes typed onto a rest are triplets too, until you pick a note length. A dotted note is never a triplet: Dotted and Triplet switch each other off.
- **Held notes, hammer-ons and slides:** T holds the note before the cursor through the cursor's beat (a tie, also across a bar line; on a rest it uses the chosen note length). H makes a hammer-on or pull-off and S a slide from the note at the cursor into the next note on that string. They're in the toolbar too (Hold, H/P, Slide), show as ties, "H"/"P" arcs and "sl." lines, and play legato: the next note isn't picked again. On SoundFont tracks this bends the whole track, so it's meant for single-note lines.
- **Playback:** Space plays from the cursor. "⟲ Loop" (L) repeats what you pick next to it: the whole song, a section or the selected bars (it stays put while you click around); "Metronome" (M) clicks along. The speed next to it (25–200 %) plays slower or faster to practice: notes keep their pitch, the song keeps its tempo, and exports are not affected; MIDI recording follows it too (count-in included). Sound effects always play at their own speed. The meter after it shows the master level (left and right, with the last peak marked); its light turns red once the mix clips (click it to reset). Each track has M (mute) and S (solo). Zoom the score with − / + or Ctrl + mouse wheel.
- **Audio latency:** on Linux the app uses a small audio buffer (256 samples), so the MIDI keyboard sounds about 30 ms after a key press. If playback crackles, pick "Standard" under ☰ → Audio and MIDI settings, and restart the app. The same page picks the audio output the app plays through (remembered on this computer).
- **Tuning and capo:** "Tuning" on a guitar or bass track's card opens its tuning: pick a preset (Drop D, DADGAD, Open G, half or whole step down, …) or tune each string up or down by semitones (click a string to hear it, "▶ Strum" for all), and put a capo on a fret. Frets in the tab count from the capo, as players read them. For notes already written you choose: keep how they sound (the frets change, and a note its string can't reach moves to a free string) or keep the tab as it is. A tuning other than standard is listed under the song title, and the capo is noted over the first bar; recording and step input fret for the tuning and capo.
- **Page view and PDF:** "Pages" (bottom right, next to "Screen") shows the score on A4 pages, black on white as it is printed; you can edit and play it as usual. Export → PDF saves those pages as a PDF, with the tracks and staves shown in the score.
- **Audio export for Unity:** Export → Audio (WAV, OGG)… exports the whole song, a section or a bar range at 48 or 44.1 kHz, as a 16-bit, 24-bit or 32-bit float WAV, or as OGG Vorbis (much smaller, in five qualities; Unity imports it as it is). "Loop seamlessly" (the default) makes the file exactly as long as its bars and mixes what still rings at the end (reverb, echo, held notes) back onto its start, so it loops without a gap or a click when *Loop* is ticked on the Unity AudioSource, and the first bar already has the last one's tail in it; "Cut at the end" makes it as long without that (with a 5 ms fade), for music that doesn't loop; "Let notes ring out" adds a 1.5 s tail instead. Muted tracks are left out, so solo a track to export it on its own. "One file per track (stems)" saves each track as a file of its own instead, into a folder you pick (named "Song - Track.wav", or "Song - Section - Track.wav" for a section; files with the same names are replaced). Tick the tracks to export: the ones you hear in the mix that play in the range are ticked to start with, and a muted track can be ticked too. Next to each track you can name the stem it goes into: tracks with the same stem name share one file (e.g. "Rhythm" for the drums and the bass, saved as "Song - Rhythm.wav"); the stem names are saved with the project. "Also the mix" saves the whole mix into the same folder too ("Song.wav"). The dialog remembers whether you exported stems or the mix. Each stem sounds as its tracks do in the mix (sound, volume, pan, master bitcrusher), and all of them are exactly the same length, so in Unity they play in sync as layers: one AudioSource each, started at the same time (e.g. with `PlayScheduled`), and a layer faded in or out by its volume.
- **Beat map and Unity player:** "Also a beat map (JSON)" in Export → Audio… saves a `.json` file next to the mix or the stems, named like the mix ("Song.json"): the tempo, time signature, seconds per beat and bar, where each bar starts and how many beats it has (so tempo and time-signature changes are followed), where each section starts and ends (in seconds and in bars, counted from the first exported bar), whether the files loop, and which files belong to it. Export → Unity player script (C#)… saves `GameMusicPlayer.cs` (also in this repository under `unity/`): put it and the exported files into your Unity project's Assets, add it to a GameObject, drag the audio files into *Layers* and the `.json` into *Beat Map*. It starts all layers at the same moment and loops them; from your scripts, `SetLayer("Drums", 1f, 2f)` fades a layer in over 2 seconds and `SetLayerOnNextBar("Lead", 0f)` stops one at the next bar line. With the beat map, the events `OnBeat` and `OnBar` fire as beats and bars start, and `CurrentBar`, `CurrentBeat` and `CurrentSection` say where the music is. Layer names come from the file names ("Song - Drums.wav" is the layer "Drums").
- **Sound effects:** the "Sound effects" tab (next to Arrangement) keeps your game's sound effects in the project, next to the song: jump, coin, laser, … Each one has its own name, sound, notes and tempo, and isn't part of the music. "+ New" starts one from a template (Jump, Coin, Laser, Hit, Explosion, Power-up, Blip: a ready-made 8-bit sound with its notes, played right away) or empty; draw its notes in the piano roll and pick or shape its sound with the button next to its name (the same sound window as for tracks). The colors next to its name mark it in the list with a stripe, to tell kinds of effects apart at a glance (e.g. every jump teal, every hit pink); effects from a template start with its color, and "No color" (the crossed-out dot) takes it away. "Vary" nudges the sound's settings at random and plays it: the same kind of sound, a little different (press it again for another try, Ctrl+Z to go back, "Duplicate" first to keep the one you have). ▶ plays one, "▶ Play all" plays them one after the other as they are exported, to hear if they fit together. Keys 1–9 play the first nine (each card shows its key) over whatever plays: start the song with ▶ at the top and press them as you would in your game, to hear whether the coin clashes with the music or the jump is too loud. While the song plays, ▶ on a card plays the effect over it too. Effects are heard as they are exported, at their own level and not through the song's master bitcrusher, as in a game. "Export…" (also Export → Sound effects in the top bar) saves them all into a folder as WAV (16-bit, 24-bit or 32-bit float) or OGG, one file each named after the effect (files with the same names are replaced, so exporting again updates them in your game), or only the one picked. Each file ends when its sound has faded, with a tiny fade; it can be mono (the default) and normalized to −1 dB.
- **Keys tracks:** "+ Keys" adds a track for keyboard parts (synth leads, pads, piano), shown in standard notation. When the cursor is on it, a piano roll opens under the score: drag to draw a note, click a note to remove it. "● Record MIDI" in the piano roll records what you play on a MIDI keyboard (one-bar count-in, metronome, the rest of the song plays along) and snaps it to the grid. "Step input" in the toolbar enters keys you play at the cursor with the chosen length, on any track (chords: press keys together; on guitar and bass the string and fret are chosen for you). MIDI keyboards are found automatically. "Import MIDI…" adds the tracks of a `.mid` file.
- **Drums:** "+ Drums" adds a drum track. Its bar at the cursor shows up as a step grid: click to add or remove hits (Shift+click = accent, Alt+click = ghost note), switch between 1/8, 1/16 and 1/32 steps or triplets (1/8T, 1/16T: three steps where two straight ones go; a bar with triplets shows in the triplet grid by itself), start from a pattern and repeat a bar into the following ones. Drums play the General MIDI kit, or an 8-bit kit after "★ Make it retro"; the pencil next to its sound shapes each drum of that kit. MIDI export puts drums on channel 10, as Unity and other tools expect.

## Development

Requires Node.js 22.12 or newer (developed with Node 26 / npm 12).

```bash
npm install
```

```bash
npm run dev
```

Starts the Electron app with live reload.

```bash
npm run dev:web
```

Runs the UI in a normal browser at http://localhost:5173 (file saving falls back to downloads).

```bash
npm test
```

```bash
npm run typecheck
```

## Building

```bash
npm run dist:linux
```

Creates `release/GameMusicApp-<version>-x86_64.AppImage`.

The Windows installer and portable `.exe` are built by GitHub Actions for every pull request and every push to `main` (`.github/workflows/build.yml`); download them from the run's artifacts. To build another branch, use *Actions → Build → Run workflow*. `npm run dist:win` works on Windows.

```bash
npm run smoke
```

Starts the last build headless, checks that the UI and score render without errors, and quits.

```bash
npm run licenses
```

Writes `THIRD_PARTY_LICENSES`, the licenses of every library, font and sound the app contains; it is packaged next to the app. Run it after adding or updating a dependency (`npm test` fails when one the app imports isn't listed there in its installed version).
